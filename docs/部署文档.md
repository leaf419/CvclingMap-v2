# BikeFlowGNN v2 部署文档（GeoScene 杯 C 组 · 规则第 5 条合规）

> 本部署文档面向比赛交付，核心目标是满足《比赛规则第 5 条》：
> **"服务器端部署如完全脱离 GeoScene 服务器端产品，则属于无效产品"**。
> 因此本项目服务器端 GIS 核心强制基于 **GeoScene Enterprise Server**（网关层 REST 集成与地图服务代理），
> 前端三维渲染采用 Three.js（开源仅用于可视化部分功能，允许）。

---

## 一、规则第 5 条合规解读与本项目对应关系

| 规则要求 | 本项目实现 | 位置 |
|---|---|---|
| 基于 GeoScene 平台产品二次开发（Server / Pro / Web API / Runtime SDK） | GeoScene Enterprise Server 作为服务器端 GIS 核心（地图服务发布与 REST 代理） | `gateway/service/geoscene_client.py`、`gateway/api/routes.py`、`tools/geoscene/` |
| 结合 Portal 可定制 Apps（Web AppBuilder / Insights 等，可选） | 服务器端部署基于 Server，可后续接入 Portal 发布；本作品以 Web 应用形式交付 | `tools/geoscene/server_config.json` |
| 允许部分功能使用开源技术 | Three.js 3D 场景、PyTorch/PyG 图神经网络、city2graph、NSGA-II 均属"部分功能"开源增强 | `algorithm/`、`frontend/src/rendering/Scene3DView.tsx` |
| 服务器端部署必须基于 GeoScene 服务器端产品（强制） | **网关经 REST 加载 Server 已发布的 GIS 服务**（街道段/停车点/场景服务）；服务不可达时才回退本地数据（仅开发模式） | `gateway/api/routes.py` 代理端点、`gateway/service/geoscene_client.py` |
| 三维类作品并入本组 | 前端 Three.js 3D 场景（建筑白模 + 路网 + 路线管线） | `frontend/src/rendering/Scene3DView.tsx` |

**部署架构拓扑：**

```
浏览器 (Three.js 3D 场景)
   │  HTTP
   ▼
FastAPI 网关 (gateway, :8000) ──代理──► GeoScene Enterprise Server (:6443/arcgis)
   │  REST /api/geoscene/proxy/...          │ 已发布地图/场景/地理编码服务
   │                                        ▼
   └──► database/ (SQLite)  +  File Geodatabase（交付格式，tools/geoscene/data/）
   └──► algorithm/（纯算法引擎，开源技术）
```

## 四、部署步骤

### 步骤 1：部署 GeoScene Enterprise Server（服务器端 GIS 核心）

1. 安装并启动 GeoScene Enterprise Server（本机默认 `https://localhost:6443/arcgis`，远程服务器同理）。
2. 在 Server 管理后台为网关生成 Token（发布服务与代理访问需要）。
3. 填写 `.env` 中的 `BIKEFLOW_GEOSCENE_SERVER_URL` 与 `BIKEFLOW_GEOSCENE_SERVER_TOKEN`。

验证连接：

```powershell
python -c "from gateway.service.geoscene_client import geoscene_client as c; import json; print(json.dumps(c.status(), ensure_ascii=False, indent=2))"
```

### 步骤 2：生成输出数据与 File Geodatabase（交付格式）

```powershell
# 生成 GeoJSON 输出（segments/stations/routes/scene_config）
python tools/geoscene/publish_services.py --generate

# 构建 File Geodatabase（比赛推荐交付格式）
python tools/geoscene/build_fgdb.py
```

> 本机若已安装 GeoScene Pro（arcpy 可用）或 GDAL（含 FileGDB 写驱动），脚本直接生成真正的
> `tools/geoscene/data/BikeFlowGNN.gdb`；否则生成 `BikeFlowGNN_delivery/` 交付包
> （GeoJSON + `import_to_fgdb.py`），在 GeoScene Pro 的 Python 窗口运行即生成 `.gdb`。

### 步骤 3：发布 GeoScene 服务

**方式 A — GeoScene Pro 手动发布（推荐，最稳妥）：**

1. GeoScene Pro → 新建工程 → 地图。
2. 添加数据：从 `BikeFlowGNN.gdb` 导入 `StreetSegments`、`BikeStations`。
3. 右键图层 → 共享 → 发布为 Web 图层 → 选择 GeoScene Enterprise Server 连接。
4. 服务参数参照 `tools/geoscene/server_config.json`（字段定义、渲染符号）。

**方式 B — 脚本自动发布（需 Server Token）：**

```powershell
python tools/geoscene/publish_services.py --publish
```

发布后验证服务：

```powershell
python tools/geoscene/publish_services.py --check
# 期望输出: ✓ 所有 GIS 核心服务均已发布
```

### 步骤 4：部署网关（FastAPI + GeoScene 代理）

```powershell
deploy\start_gateway.ps1
# 或手动:
uvicorn gateway.app:app --host 0.0.0.0 --port 8000
```

验证：
- `http://localhost:8000/api/health` → `{"status": "ok", "version": "2.0.0"}`
- `http://localhost:8000/api/geoscene/status` → `available: true` 且各服务 `available: true`
- 代理可用：`http://localhost:8000/api/geoscene/proxy/segments/query?where=1%3D1&f=geojson`

### 步骤 5：部署前端（Three.js 3D 场景）

**开发模式：**

```powershell
deploy\start_frontend.ps1
# http://localhost:5173
```

**生产模式：**

```powershell
deploy\build_all.ps1        # 产出 frontend/dist
# 用任意静态服务器托管 dist，并将 /api 反向代理到网关 :8000
```

前端行为：
- Three.js 3D 场景（建筑白模 + 路网 + 路线管线叠加），数据从网关 `/data`（或本地 `/data`）静态加载。
- 网关 GeoScene 集成状态可随时查看：`http://localhost:8000/api/geoscene/status`。

## 六、生产服务器部署（Linux / Windows）

> 前提：本地联调已通过（数据库已入库、输出数据已生成、前端可运行）。
> 生产环境三件套：**GeoScene Enterprise Server（GIS 核心）+ FastAPI 网关 + 前端静态托管**。

### 6.1 服务器前置：部署 GeoScene Enterprise Server

1. 在服务器安装 GeoScene Enterprise Server（Windows Server / Linux 均可，默认端口 6443），使用比赛组委会提供的许可授权。
2. 启动后生成网关访问用的 Server Token。
3. 将 `BikeFlowGNN.gdb`（File Geodatabase）上传到服务器，在 GeoScene Pro（或 Server Manager）中发布：
   - `StreetSegments` → `BikeSegments_MapService`（MapServer）
   - `BikeStations` → `BikeStations_MapService`（MapServer）
   - 3D 场景 → `Beijing3D_WebScene`（SceneServer）
   - 服务参数参照 `tools/geoscene/server_config.json`。
4. 验证：浏览器访问 `https://<服务器IP>:6443/arcgis/rest/services/BikeSegments_MapService/MapServer?f=json`。

### 6.2 上传项目与数据

```bash
# 服务器（Linux 示例，路径 /opt/bikeflow）
git clone <仓库> /opt/bikeflow   # 或 rsync/scp 上传整个项目
cd /opt/bikeflow

# Python 虚拟环境 + 依赖
python3 -m venv .venv && source .venv/bin/activate
pip install -r gateway/requirements.txt

# 环境变量
cp .env.example .env
# 编辑 .env:
#   BIKEFLOW_GEOSCENE_SERVER_URL=https://<服务器IP>:6443/arcgis
#   BIKEFLOW_GEOSCENE_SERVER_TOKEN=<Token>
#   BIKEFLOW_GATEWAY_HOST=127.0.0.1   BIKEFLOW_GATEWAY_PORT=8000

# 数据就绪（三选一，通常直接使用随项目上传的已入库文件即可）
python database/scripts/ingest_all.py          # 如需重新入库（131s）
python tools/geoscene/publish_services.py --generate   # 重新生成输出 GeoJSON
python tools/geoscene/build_fgdb.py                     # 构建 File GDB 交付包
```

### 6.3 网关生产运行（守护进程）

**Linux（systemd）**：`/etc/systemd/system/bikeflow-gateway.service`

```ini
[Unit]
Description=BikeFlowGNN Gateway (FastAPI + GeoScene)
After=network.target

[Service]
WorkingDirectory=/opt/bikeflow
EnvironmentFile=/opt/bikeflow/.env
ExecStart=/opt/bikeflow/.venv/bin/uvicorn gateway.app:app --host 127.0.0.1 --port 8000
Restart=always
RestartSec=3

[Install]
WantedBy=multi-user.target
```

```bash
sudo systemctl daemon-reload
sudo systemctl enable --now bikeflow-gateway
sudo systemctl status bikeflow-gateway
```

**Windows（NSSM 或计划任务）**：

```powershell
nssm install BikeFlowGateway "C:\Python313\python.exe" "C:\CvclingMap\gateway\run_gateway.py"
nssm set BikeFlowGateway AppDirectory "C:\CvclingMap"
nssm set BikeFlowGateway AppEnvironmentExtra BIKEFLOW_GEOSCENE_SERVER_URL=https://127.0.0.1:6443/arcgis
nssm start BikeFlowGateway
```

### 6.4 前端静态托管（nginx）

```bash
# 在开发机构建（已含 dist），或服务器上构建：
cd frontend && npm install && npm run build
```

`/etc/nginx/sites-available/bikeflow.conf`：

```nginx
server {
    listen 80;
    server_name bikeflow.example.com;            # 或服务器 IP
    root /opt/bikeflow/frontend/dist;
    index index.html;

    gzip on;
    gzip_types text/css application/javascript application/json;

    # SPA 路由回退
    location / {
        try_files $uri $uri/ /index.html;
    }

    # API 反代到 FastAPI 网关
    location /api/ {
        proxy_pass http://127.0.0.1:8000;
        proxy_set_header Host $host;
        proxy_set_header X-Real-IP $remote_addr;
        proxy_read_timeout 120s;                 # 路线搜索可能较慢
    }

    # 输出数据（网关已静态挂载 database/output -> /data）
    location /data/ {
        proxy_pass http://127.0.0.1:8000;
    }
}
```

```bash
sudo ln -s /etc/nginx/sites-available/bikeflow.conf /etc/nginx/sites-enabled/
sudo nginx -t && sudo systemctl reload nginx
```

## 七、常见问题

| 现象 | 原因与处理 |
|---|---|
| `/api/geoscene/status` 返回 `available: false` | GeoScene Server 未启动，或 `.env` 中 `BIKEFLOW_GEOSCENE_SERVER_URL` 错误；前端会自动回退本地数据（开发模式），比赛交付前必须部署 Server |
| 服务 `available: false` | 服务未发布或 Token 无效；按步骤 3 发布服务并配置 Token |
| 3D 场景空白 | 检查网关是否启动（:8000）、浏览器控制台 `/data` 请求是否 404；`frontend/public/data/` 需含 `segments/buildings/beijing_districts_osm` 等 GeoJSON |
| 3D 场景无建筑白模 | `database/output/` 下缺少 `buildings.geojson`；先运行 `python tools/geoscene/publish_services.py --generate` |
| `build_fgdb.py` 提示仅生成交付包 | 本机无 arcpy/GDAL FileGDB 驱动；在 GeoScene Pro 中运行交付包内 `import_to_fgdb.py` 生成 `.gdb` |
